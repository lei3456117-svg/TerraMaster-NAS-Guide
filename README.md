## 一、 网络架构与两套 IP 核心法则（必读）

很多新手最大的困惑是：**为什么挂载了网络硬盘，有时飞快（100MB/s），有时奇慢还卡死？**  
根源在于没有分清 **「物理内网」** 与 **「虚拟远程」** 两个不同的网络入口：

| 使用场景 | 推荐挂载地址 | 连接通道 | 实测延迟 | 传输带宽 | 适用操作 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **公司办公室内** | `smb://192.168.1.198` | 局域网千兆物理交换 | **0.4ms ~ 0.8ms** | **110MB/s ~ 280MB/s**（秒传几十 G 视频） | 日常大文件读写、视频剪辑、工程协同 |
| **家中 / 出差异地** | `smb://100.87.114.20` | Tailscale P2P 加密隧道 | **19ms ~ 35ms** | 跑满公司宽带上行上限（30~100Mbps） | 远程办公、调取资料、轻量存取 |

> ⚠️ **核心法则（切记）**：
> - **人在公司**：必须连 `192.168.1.198`！切勿在办公室使用 `100.x.x.x` 虚拟 IP，否则会触发路由器的 NAT 回环（Hairpinning）限制，导致内网数据绕道境外香港/新加坡节点，速度骤降！
> - **离开公司**：保持 Tailscale 开启，使用 `100.87.114.20` 实现秒级远程穿透。

## 二、 铁威马 NAS 端部署（TOS 6 + Docker）

### 1. 为什么装在 NAS 而不是路由器上？
- **硬件对比**：公司路由器（如 Newifi D2）闪存仅 32MB，缺少硬件加密，跑 Go 编译的 Tailscale 极易闪退或跑满 CPU；而铁威马 F4-423 拥有 Intel N5095 四核处理器 + 4GB 内存，自带硬件 AES-NI 加密指令，在 Docker 中运行负载几乎为 0%。

### 2. Docker Compose 项目部署步骤
1. 打开 Tailscale 官网后台（`https://login.tailscale.com/admin/settings/keys`），点击 **「Generate auth key」**，复制以 `tskey-auth-` 开头的密钥。
2. 登录铁威马 TOS 桌面，打开 **「Container Manager」**（容器管理器）。
3. 点击左侧 **「项目」** -> 点击 **「新增」**：
   - 项目名称：`tailscale`
   - 配置文件来源：选择 **「创建 docker-compose.yml」**（在线编辑）
4. 粘贴以下配置文件（将密钥替换为您实际生成的 Key）：
   ```yaml
   version: "3.7"
   services:
     tailscale:
       image: tailscale/tailscale:latest
       container_name: tailscale
       hostname: terramaster-nas
       network_mode: host
       privileged: true
       volumes:
         - /dev/net/tun:/dev/net/tun
         - tailscale-data:/var/lib/tailscale
       environment:
         - TS_AUTHKEY=tskey-auth-xxxxxxxxxxxxxx  # 填入实际密钥
         - TS_STATE_DIR=/var/lib/tailscale
         - TS_USERSPACE=false
       restart: unless-stopped

   volumes:
     tailscale-data:
   ```
5. 点击「保存 / 应用」，回到项目列表，**手动点击右侧的滑块开关将其拨至开启（绿色）**。
6. 进入 Tailscale 网页端 `Machines` 列表，找到 `terramaster-nas`，点击右侧 `...` 菜单选择 **「Disable key expiry」**（禁用密钥过期），确保护航永不断连。

## 三、 客户端挂载与日常使用（Mac / Windows / 移动端）

### 1. 两个分区的区别：个人私密盘（depp）vs 公共协作盘（public）

铁威马系统基于 Linux Samba，共享分区逻辑如下：
- **公共协作盘（`public`）**：出厂默认公共空间。所有人（只要分配了账号密码）都可以访问，适合团队公用资料交换。
- **个人独立私有盘（`depp`）**：在系统开启「用户家目录服务」后自动生成的专属空间。系统会以你的**登录用户名**命名该文件夹（即 `depp`，而非字面意义上的 `home`）。其他账号在网络中看不见、也进不去，适合存放私人文件、视频、账号备份。

### 2. Mac 端挂载与开机自动静默连接

#### (1) 推荐方式：纯 IP 挂载（让系统弹窗列出所有盘）
1. 在 Mac 访达按下快捷键 **`Command + K`**（或点击屏幕顶部菜单「前往 -> 连接服务器...」）。
2. 输入地址：
   - 办公室：`smb://192.168.1.198`
   - 家中外网：`smb://100.87.114.20`
3. 点击「连接」，身份务必选择 **「注册用户」**，输入用户名（`depp`）和密码，**勾选「在我的钥匙串中记住此密码」**。
4. 弹出的文件夹选择框中，按住 `Command` 键**同时勾选 `depp` 和 `public`**，点击确定。两个盘符立即挂载在桌面上。

#### (2) 设置 Mac 开机自动静默挂载
1. 打开 Mac「系统设置 -> 通用 -> 登录项与扩展」。
2. 在「登录时打开」列表中点击底部的 **`+`** 号。
3. 依次将桌面上的 **`depp` 磁盘**、**`public` 磁盘** 以及应用程序里的 **`Tailscale.app`** 添加进去。
4. 页面往下拉到「在后台允许」，确保 **Tailscale** 的开关处于开启状态。
5. 今后无论合盖唤醒还是重启 Mac，电脑联网后系统会自动在后台静默挂载两个盘符。

### 3. Windows 电脑映射为本地网络驱动器（Z: 盘）
1. 键盘按下 **`Win + R`** 呼出运行窗口，输入：
   - 办公室：`\\192.168.1.198`
   - 家中外网：`\\100.87.114.20`
2. 输入账号密码并勾选 **「记住我的凭据」**。
3. 看到 `depp` 和 `public` 文件夹后，右键点击想要长期挂载的文件夹 -> 选择 **「映射网络驱动器」**。
4. 分配盘符为 `Z:`，勾选 **「登录时重新连接」**，点击完成。该共享盘便永久固定在「此电脑」中。

### 4. 手机与平板端访问
- **苹果 iOS**：自带「文件」App -> 右上角 `...` ->「连接服务器」-> 输入 `smb://100.87.114.20`。
- **安卓 Android**：推荐使用「FE 文件管理器」或系统自带文件管理添加 SMB 共享。

## 四、 如何安全分享给朋友或同事（零泄密与分级方案）

文档中已提供 3 种针对不同场景的具体分享方案，彻底解决账号安全与配额疑虑：

### 1. 场景 A：同办公室同事（零安装，极速千兆直连）
- **适用场景**：同事电脑也在公司办公区。
- **特别避坑（导致同事延迟超高的两大死因）**：
  1. **Wi-Fi 连错网段**：同事若连了「公司公用大 Wi-Fi」，与工位 Newifi 处于两层隔离网络，无法直通；**必须让同事连工位 Newifi 的独立 Wi-Fi**。
  2. **在公司错用 100 虚拟 IP**：若在公司内网输入 `100.87.114.20`，会触发 NAT 回环失败，流量被迫绕行境外香港/新加坡 DERP 节点（延迟飙升至 700ms 且限速 2Mbps）。
- **正确操作（秒降至 0.5ms 满速）**：
  1. **同事完全不需要安装 Tailscale**。
  2. 在铁威马后台给同事建一个普通账号（属于 `users` 组，仅开放 `public` 文件夹）。
  3. 确认同事连接工位 Newifi Wi-Fi 后，直接在 Mac 按 `Cmd + K` 输入 `smb://192.168.1.198/public`（Windows 输入 `\\192.168.1.198\public`），即享 100MB/s 满速。

### 2. 场景 B：异地 / 居家办公同事（Tailscale 设备单机分享）
- **适用场景**：外地出差、居家办公或跨网络长期协同。
- **关于「免费额度与账号」的明确规则**：
  - **设备 vs 人数**：你自己的 Mac、Windows、手机挂在同一个账号下，**只算 1 个用户（3 台设备）**，不占团队多用户配额。
  - **绝不交出主账号**：绝对不要把你的微软主账号给同事！
  - **单机分享机制（Share Machine）**：
    1. 登录 [Tailscale 管理后台](https://login.tailscale.com/admin/machines)。
    2. 找到 `terramaster-nas`，点击右侧 `...` -> 选择 **「Share...」**，生成专用分享链接。
    3. 同事在自己电脑安装 Tailscale，用他**自己的微软或苹果账号**登录（**严禁使用谷歌账号**，防止国内无代理无法激活）。
    4. 同事点击链接点击「Accept」。同事的 Tailscale 里**仅能看到这台 NAS**，完全看不到你的 Mac、Win 等其他私有电脑。
    5. 同事按快捷键挂载 `smb://100.87.114.20/public`。

### 3. 场景 C：临时传文件（免装任何软件，网页提取码）
- **适用场景**：临时给同事/客户发送大文件或工程包，对方无需安装 Tailscale，也不需要分配 NAS 账号。
- **操作方式**：
  1. 浏览器登录铁威马 TOS 桌面，打开「文件管理」。
  2. 右键点击目标文件夹或视频，选择 **「创建分享」**。
  3. 生成网页下载链接与提取码，直接发给对方，浏览器点开即下。

### 4. 铁威马 NAS 权限隔离设置（必做）
1. 登录铁威马 TOS「控制面板 -> 用户与用户组 -> 新增」，为同事建立普通账号（用户组仅选 `users`，**严禁勾选 `admin`**）。
2. 在「控制面板 -> 共享文件夹 -> public -> 权限」，勾选该同事为「读写」。
3. 在「共享文件夹 -> depp（个人私密盘）-> 权限」，确认该同事为 **「禁止访问」**。

### 5. 微信一键通知模板（直接复制发给同事）

**【办公室内同事】：**
```text
【公司 NAS 局域网高速网盘】
1. 电脑连接工位 Wi-Fi。
2. 挂载地址：
   - Mac 用户（Cmd+K）：smb://192.168.1.198/public
   - Windows 用户（Win+R）：\\192.168.1.198\public
3. 账号：[同事用户名]   密码：[初始密码]
```

**【异地/居家办公同事】：**
```text

1. 下载并安装 Tailscale：https://tailscale.com/download
2. 使用你自己的「微软账号」或「苹果账号」登录（国内直连，请勿选谷歌）。
3. 点击管理员发给你的专属设备分享链接并接受（Accept）。
4. 电脑挂载地址：
   - Mac 用户（Cmd+K）：smb://100.87.114.20/public
   - Windows 用户（Win+R）：\\100.87.114.20\public
5. 账号：[同事用户名]   密码：[初始密码]
```

## 五、 与科学上网 / 代理软件共存配置（防断连）

### 1. Mac 端 Clash Verge 设置（避坑指南）
很多小白发现“开了代理 NAS 就断连”，是因为代理把内网流量当成外网抓走了。

1. 打开 Clash Verge 界面，**必须先开启「系统代理」开关**（激活系统网络写入权）。
2. 点击「系统代理」右侧的小齿轮 **⚙️** 进入设置。
3. **关键步骤**：将 **「始终使用默认绕过」开关关闭（灰色）**！
   > 踩坑点：若不关闭该选项，软件会强制使用写死的列表，你添加的自定义规则会在保存后被冲掉！
4. 在「当前绕过」列表中输入：
   ```text
   100.64.0.0/10
   ```
   按回车生成标签，并确认列表中已有 `192.168.0.0/16`。
5. 点击右下角 **「保存」**。此时即使代理开启，访问 NAS 也完全不受影响。

### 2. Mac 端 Antify 分应用透明代理注意事项
- **原理**：Antify 会将其名单内的软件流量直接打包送入海外代理节点。
- **唯一铁律**：打开 Antify 的软件勾选列表，**绝对不要勾选「访达（Finder）」**！只要系统文件管理器不被代理，NAS 挂载就永远畅通。

### 3. 公司路由器端 v2rayA 透明代理放行（恢复 P2P 直连）
- **现象**：终端运行 Tailscale ping 显示 `pong via DERP(hkg) in 700ms`（绕道香港中继）。
- **根因**：路由器新装 v2rayA 透明代理后，默认把未知 UDP 端口抓去海外节点，导致 Tailscale 打洞握手包迷路。
- **解决步骤**：
  1. 浏览器打开路由器代理后台：`http://192.168.1.1:2017`。
  2. 点击右上角 **「设置」**。
  3. 在「自定义分流规则」输入框中添加：
     ```text
     port(3478, 41641) -> direct
     ip(100.64.0.0/10) -> direct
     ```
  4. 点击保存并应用。终端重新测试，香港中继消失，恢复为十几毫秒的 P2P 满速直连。

## 六、 路由器底层打洞与防火墙（管理员技术备忘）

针对公司两层 NAT 架构（上级光猫/企业路由 `172.16.x.x` + 二级 Newifi D2 路由 `192.168.1.x`）：

### 1. 静态端口转发（OpenWrt 官方原版）
路径：`网络 -> 防火墙 -> 端口转发`，确认添加以下规则：
- **名称**：`tailscale`
- **协议**：`UDP`
- **外部端口**：`41641`
- **内部 IP**：`192.168.1.198`
- **内部端口**：`41641`

### 2. 关于「Full Cone NAT」的辟谣与真相
- **真相**：若重装的是 **OpenWrt 官方原版（基于 firewall4 + Linux 6.12 内核）**，官方 Web 界面中**本来就没有 Full Cone NAT 的勾选项**（该选项是国内第三方 ImmortalWrt/LEDE 固件自行添加的补丁）。
- **结论**：官方版固件只要配置好上方的 `UDP 41641` 静态映射，配合 v2rayA 放行 UDP，即可完美实现外部打洞，无需纠结寻找 FullCone 菜单。

## 七、 小白实战高频踩坑与秒解字典（8 大翻车实录）

| 序号 | 常见翻车现象 | 根本原因 | 10秒秒解方案 |
| :---: | :--- | :--- | :--- |
| **1** | 桌面替身图标一直转圈卡死，按 `Cmd + Q` 无法退出 | 替身记录了服务器根路径，网络波动时 NetBIOS 广播超时导致访达假死；系统禁止退出核心守护进程访达 | 终端运行 `killall Finder`（或按 `Option+Cmd+Esc` 重新开启访达），删除假替身，改用系统原生挂载 |
| **2** | 访达连接 NAS 提示「连接失败」 | Mac 默认以「客人（免密）」身份连接，铁威马安全策略拒绝匿名访问 | 点击窗口右上角「连接身份...」切换为「注册用户」，输入账号密码并记住 |
| **3** | 输入 `smb://.../home` 报错「服务器上不存在该共享」 | 铁威马开启家目录后，个人私有盘默认是以你的用户名命名的（如 `depp`）而非通用的 `home` | 直接按 `Cmd + K` 输入纯 IP（`smb://192.168.1.198`），在弹窗中点选自己的名字 |
| **4** | 重启 Mac 后 NAS 盘全掉，报错找不到服务器 | 电脑重启后 Tailscale 处于未启动（Stopped）状态，登录项先尝试挂载因而报错 | 在 Tailscale 设置勾选 `Launch Tailscale at login`，并在 Mac 系统设置登录项中放行 |
| **5** | 在办公室办公，拖拽大文件速度只有几百 KB/s 极慢（或同事直连延迟超高） | ① 同事在公司连了虚拟 IP（`100.x`）触发回环中继；② 同事连的是「公司总 Wi-Fi」而非「工位 Newifi Wi-Fi」，被路由器防火墙阻断；③ 同事电脑开启了代理全局模式 | ① 确认同事连接工位 Newifi Wi-Fi；② 访问地址改用原生内网 `smb://192.168.1.198/public`（延迟立降至 0.5ms）；③ 检查同事代理设置，放行局域网 |
| **6** | 在路由器后台找不到「Full Cone NAT」开关 | 路由器运行的是 OpenWrt 官方原版（firewall4），官方版未内置国内第三方特有的补丁界面 | 无需寻找该选项，在「网络 -> 防火墙 -> 端口转发」中确认添加了 `UDP 41641` 规则即可 |
| **7** | Clash Verge 添加绕过规则保存后不生效或被冲掉 | 开启了「始终使用默认绕过」，导致软件强制使用写死列表覆盖了用户的自定义项 | 先开启「系统代理」，关闭「始终使用默认绕过」，再添加 `100.64.0.0/10` 保存 |
| **8** | 终端 Tailscale ping 显示 `via DERP(hkg)` 延迟几百毫秒 | 路由器新装的代理插件开启了全局透明代理，拦截了 Tailscale 的打洞探测包送往境外 | 在路由器 v2rayA 的设置中添加自定义规则：`port(3478, 41641) -> direct` 并应用 |
