三、 今日双路由打通全流程实录

  • 软路由 WAN 口由家庭 PPPoE 切回公司 DHCP

    软路由由于刷入的是家庭网络备份，原 WAN 口固化了家庭宽带 PPPoE 账号。将其重置为标准 DHCP 客户端：

    uci set network.wan.proto='dhcp'
uci delete network.wan.username
uci delete network.wan.password
uci commit network
/etc/init.d/network restart

    重启后 WAN 口秒级获取 192.168.1.6，网关 192.168.1.1，外网连通。

  • PassWall 2 出境透明分流服务验证

    确认 Xray 主分流与三大 Sing-box 子进程独立运行：

    • AI_APAC (端口 2006)：专属亚太台湾低延迟出口，承载 Antigravity、Gemini API、GitHub。
    • AI_US (端口 2005)：专属美国高风控原生出口，严防 Claude Code、Codex 异地漂移。
    • Default (端口 2004)：通用外网出口（YouTube、普通网站）。

  • Mac 本机 USB 网卡 DNS 缺失故障排查与修复

    故障现象：软路由通网且外网 IP 可 Ping 通，但 Mac 无法打开任何网页。
    故障根因：Mac 外接 USB 网卡 (en6) 手动配置了 IP 192.168.100.100，但 DNS 服务器一栏留空，系统无法进行域名解析。
    修复方案：注入主路由 DNS 192.168.100.1 后瞬时恢复正常：

    networksetup -setdnsservers "USB 10/100/1000 LAN" 192.168.100.1

  • ImmortalWrt 硬路由化身纯无线 AP (Dumb AP)

    进入 ImmortalWrt 的「网络 ➡️ 接口 ➡️ lan」修改：

    • IPv4 地址修改为：192.168.100.2
    • IPv4 网关填写为：192.168.100.1
    • IPv4 广播地址清空
    • 高级设置中填入自定义 DNS：192.168.100.1
    • 核心步骤：在 DHCP 服务器常规设置中，勾选 「忽略此接口」；IPv6 设置全部设为「已禁用」。

  • 铁威马 NAS 硬件接入与自动就绪

    NAS 网线插入软路由/交换机 LAN 口开机，自动通过主软路由 DHCP 获取到 192.168.100.198。实测 ping 延迟 0.89ms，Web 管理（80）与 SMB（445）均秒级连通，Tailscale 自动在线。

四、 核心原理解析：接 LAN 口 vs 接 WAN 口的本质区别

✅ 接 LAN 口（当前生产标准 · 纯二层 AP）

  • 网络层级：纯二层交换网络（Layer 2 Bridge）。
  • NAT 损耗：0 次 NAT 转换，无任何额外协议开销与延迟。
  • 广播域：全屋统一广播域，mDNS、SSDP、Bonjour 协议完全畅通。
  • 设备互访：手机连 Wi-Fi 与电脑插网线完全同级，秒搜 NAS 共享、无线投屏、AirDrop。
  • 维护要求：关闭 DHCP，IP 设在同一网段，杜绝任何网络打架。

❌ 接 WAN 口（若未重构网桥的传统接法）

  • 网络层级：三层路由网络（Layer 3 Routing）。
  • NAT 损耗：双重 NAT 转换，增加握手开销，阻碍 P2P 打洞。
  • 广播域：WAN 口防火墙默认丢弃内网广播包，广播域被割裂。
  • 设备互访：手机连 Wi-Fi 无法自动发现插在主路由上的 NAS 和打印机。
  • 特别说明：普通家用路由（小米等）之所以能插 WAN，是因为其“AP 模式”在系统底层把 WAN 口软件桥接进了 LAN 网桥。
